# GUI QA agent implementation plan

- **Date:** 2026-10-26
- **Based on commit:** `867ce7e8`, which adds the design
- **Issue:** #397
- **Branch:** `feature/gui-qa-agent`, in draft PR #404, which holds the design, this plan and the implementation, and
  resolves #397

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `gui-qa` skill and agent that run a GUI change's test plan against the fat JAR, through a QA MCP server
that starts the app with an in-process JavaFX driver and moves MIDI through virtual ports.

**Architecture:** Three new modules: `mcp` (group `ai`), the only one on the MCP Java SDK; `qa-driver` (group
`testbench`), a Java agent that reads and drives the app's scene graph over a Unix socket; and `qa-mcp` (group
`testbench`), a stdio MCP server that owns the run directory, the rig rewrite, the `sendmidi`/`receivemidi` processes
and the app's process. The skill, the agent definition, a Python decoder and the docs sit on top.

**Tech Stack:** Scala 3.9.0, JDK 25, sbt 1.13, OpenJFX 26.0.2, MCP Java SDK 2.1.0 on Jackson 2, play-json 3.0.6,
ScalaTest/ScalaMock, Python 3 stdlib `unittest`, SendMIDI/ReceiveMIDI, JXA.

**Spec:** [`2026-10-26-design.md`](2026-10-26-design.md); its inputs
[`2026-10-22-gui-qa-research.md`](2026-10-22-gui-qa-research.md),
[`2026-10-22-gui-qa-in-process-guide.md`](2026-10-22-gui-qa-in-process-guide.md) (whose `QaDriver.java` is the
driver's starting point) and [`docs/research/mcp.md`](../../docs/research/mcp.md). Where they disagree, the design
wins.

## Global Constraints

- macOS only for running QA; CI runs on Ubuntu, without `sendmidi` and `receivemidi`.
- JDK 25, Scala 3, the coding, test and documentation conventions, strict TDD (red/green/refactor), and
  `coverageSettings(stmt = 80, branch = 80)` for `mcp`, `qa-driver` and `qa-mcp`.
- OpenJFX `26.0.2`, pinned; the headless platform is selected by `-Dglass.platform=Headless` (capital H).
- MCP Java SDK `2.1.0`: `io.modelcontextprotocol.sdk:mcp-core` and `mcp-json-jackson2`, never the `mcp` bundle.
- Jackson pinned to the SDK's for every Jackson artifact across the whole build: `2.21.1`, annotations `2.21`.
- `sendmidi` and `receivemidi` run as external programs from their releases' `.pkg`; never linked or shipped (GPLv3).
- `app` depends on none of the new modules; the driver reaches the app only through `-javaagent` on the QA command line.
- Folders, IDs and packages: `ai/mcp` → `mcp`, `org.calinburloiu.music.microtonalist.ai.mcp`;
  `testbench/qa-driver` → `qa-driver`, `…testbench.driver`; `testbench/qa-mcp` → `qa-mcp`, `…testbench.qa`
  (`…` = `org.calinburloiu.music.microtonalist`).
- Runs live in `$TMPDIR/microtonalist-qa/<run>/`, `<run>` = `qa-` + 4 lowercase hex digits, e.g. `qa-3f9c`.
- A rig's `qa:<device>` becomes `{ "name": "CoreMIDI4J - <run>-<device>", "vendor": "<Unknown Manufacturer>" }`; ports
  are opened with `sendmidi virt <run>-<device> --` and `receivemidi virt <run>-<device> ts nn`.
- Nothing kills a process by name: only through the handles the server started, or recorded PIDs checked by start time.
  Another clone (`microtonalist`) may run a QA run, a dev stack or a build at the same time.
- The decoder shares no code or logic with the tuners' encoders.
- No `Thread.sleep` (scalafix); a justified one carries `// scalafix:ok DisableSyntax.threadSleep` and its reason.
- Tests: `sbtn "<module>/testOnly <class> -- -oNCXEHLOPQRMWS"`. The snippets below give each case's name and
  assertions; the implementer adds the Given/When/Then comments and the fixtures.
- Commits: `[#397] <imperative summary>`, ending with the session's `Co-Authored-By` trailer; pushed to PR #404.
- A step that needs the user (a macOS grant, approving issue edits, installing the `.pkg`s, a desktop run) waits for
  them; meanwhile, carry on with the tasks that don't depend on it.

## Review Focus

1. A click or key whose handler opens a dialog with `showAndWait` must still get an answer, and the dialog must show
   in `list_windows`: input is posted, never awaited (Tasks 9, 10).
2. Nothing but the protocol may reach the server's standard output: a stray `println` or Logback's status lines would
   corrupt it (Task 17).
3. On macOS `$TMPDIR` is under `/var`, a symlink to `/private/var`: a path in the run directory must be accepted
   either way, and a symlink inside the run directory that points out of it refused (Task 12).
4. A `send_midi` line must not smuggle a forbidden command: in another case (`DEV`), chained after an allowed one, or
   behind an embedded `\n` or `\r` (Task 14).
5. The startup sweep must leave the other clone's live run alone, and never signal a PID that now belongs to another
   process (Task 16).

## Decisions the design left to the builder

| Question | Decision |
| -------- | -------- |
| Driver protocol | One JSON object per line over a Unix socket at `<run>/d.sock`; the server listens, the driver connects and says hello once a window shows |
| Where its types live | `…testbench.driver.protocol`, free of JavaFX; `qa-mcp` depends on `qa-driver` for it and loads no other driver class |
| Tools, schemas, dump format, run ID | Task 17's table; the guide's dump lines; `qa-xxxx` |
| Pointing the server at a stand-in | `MTLIST_QA_APP_JAR`, read by `bin/mtlist-qa-mcp`, for runs by hand; the acceptance run copies the stand-in's JAR to the default path, an ignored build output, so that Claude Code needn't restart |
| Skill layout, preload | `SKILL.md` for the builder; the agent reads `agent-reference.md`, no `skills:` preload |
| A killed server's processes | The next server's startup sweep (Task 16); every server SIGTERMs its processes when its input ends |
| Server against the real driver in a child JVM | No test; the smoke run (Task 22) and the acceptance run cover it |

- Produces, in `…testbench.driver.protocol`, with no JavaFX import, since `qa-mcp` uses it:

```scala
enum MouseButtonName { case Primary, Secondary }
enum DriverRequest {
  case Windows
  case Dump(window: Option[Int])
  case Snapshot(window: Option[Int], selector: Option[String], scale: Double)
  case Click(selector: String, window: Option[Int], button: MouseButtonName, clickCount: Int)
  case Key(key: String)
  case Type(text: String)
  case Idle
  case ReadClipboard
  case WriteClipboard(text: String)
}
final case class Envelope(id: Long, request: DriverRequest)
enum DriverResponse {
  case Ok(id: Long, result: JsObject)
  case Failed(id: Long, message: String)
}
final case class Hello(pid: Long, platform: GuiPlatform)
object Protocol { // one JSON object per line, no newline inside
  def encode(envelope: Envelope): String
  def decodeEnvelope(line: String): Either[DriverResponse.Failed, Envelope] // id -1 when unreadable
  def encode(response: DriverResponse): String
  def decodeResponse(line: String): Either[String, DriverResponse]
  def encode(hello: Hello): String
  def decodeHello(line: String): Either[String, Hello]
}
```

  The result of each request: `Windows` and `Dump` → `{"windows":[…]}`; `Snapshot` →
  `{"png":<base64>,"width":…,"height":…}`; `Click` → `{"matchedBy":…,"node":…,"disabled":…}`; `ReadClipboard` →
  `{"text":<string or null>}`; the others → `{}`.
- Produces, in `…testbench.driver`:

```scala
// args: the socket's path; runs a DriverLink on the daemon thread "qa-driver"
object QaDriverAgent { def premain(args: String): Unit }
final class FxExecutor(timeout: FiniteDuration = 10.seconds) {
  def apply[T](body: => T): T   // on the FX Application Thread; DriverException on timeout, or with the body's message
  def post(body: => Unit): Unit // Platform.runLater, not awaited
  def idle(): Unit              // apply(()) twice, to let a pulse pass
}
final class DriverLink(socket: Path, handler: RequestHandler, fx: FxExecutor) extends Runnable
final class RequestHandler(fx: FxExecutor) { def handle(request: DriverRequest): JsObject } // Task 9 adds an Input
final class DriverException(message: String) extends RuntimeException(message)
```

  `DriverLink.run` polls every 200 ms, on a daemon `ScheduledExecutorService`, until the toolkit runs and a window
  shows; connects; writes `Hello(ProcessHandle.current.pid, GuiPlatform.current)`; then answers one request at a time
  until the socket closes. `RequestHandler` handles `Idle` in this task; Tasks 7–11 add the others. The driver may use
  only JavaFX, the Scala 3 library and play-json, the app JAR's: it logs to `System.err`, with no logging library.

  - MTS octave tuning, `system-exclusive hex <7E|7F> <device> 08 <08|09> <ff> <gg> <hh> <data> dec`:

  ObjC.import('CoreGraphics');

  function run(argv) {

    const list = ObjC.castRefToObject(
      $.CGWindowListCopyWindowInfo($.kCGWindowListOptionOnScreenOnly, $.kCGNullWindowID));
    const ids = ObjC.deepUnwrap(list).filter(w => w.kCGWindowOwnerPID === pid).map(w => w.kCGWindowNumber);
    return JSON.stringify({ granted: $.CGPreflightScreenCaptureAccess(), windowIds: ids });
  }
